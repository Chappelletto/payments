# Git

## Новая ветка
1. переключаемся в main - `git checkout main`
2. обновляем локальную версию ветки `main` - `git pull origin main`
3. создаём новую ветку - `git checkout -b branch_name`

#### Название ветки (branch_name)
`feature/PAYMENTS-123_description`

- `feature` - это у нас будет константа. Может быть `fix`/`hotfix`/e.t.c
- `PAYMENTS` - это пространство имён задачи (название доски в tracker-е), у нас будет всегда константа.
- `123` - это номер задачи из tracker-а
- `description` - краткое описание о чём задача

## Обновление ветки, в которой ты сейчас работаешь
Причин, почему может понадобиться обновление воетки, может быть несколько. Вот основные:
- тебе нужны правки из другой ветки (например из главной main/staging)
- кто-то запушил коммиты в твою ветку (это большая редкость и так делать не стоит)

### Сначала первый вариант, когда тебе нужно забрать код из соседней ветки.
- Для этого переходим в ветку, откуда хотим получить обновления (перед этим убедись, что `git status` не показывает изменённых файлов)
- обновляем ветку `git pull origin main_branch_name`
- возвращаемся в нашу ветку `git checkout feature_branch_name`
- и делаем rebase: `git rebase main_branch_name`

Это затащит коммиты из `main_branch_name` в `feature_branch_name` и **ИЗМЕНИТ** историю коммитов.
Коммиты, которые ты затащил из `main_branch_name` окажутся **ДО** всех твоих коммитов, которые ты сделал в текущей ветке.

Т.е git будет думать, что сначала написали код в `main_branch_name`, а потом ты уже написал свой.
Могут возникать конфликты. Это отдельная тема для разговора.

После этого, нужно будет пушить код. Gitlab скажет, что история поменялась, пуш отклонён. Т.е код он твой не заберёт.
Для этого есть опция `--force`, которая <u>**ПЕРЕПИШЕТ**</u> историю в ветке, но уже в gitlab. Грубо говоря, ты полностью заменишь
ветку в gitlab на свою локальную версию. А это значит, что коммиты, которые лежат в gitlab, но не лежат у тебя, сотрутся.
Так делать можно, только когда это твоя персональная ветка. Там можешь чудить что хочешь. <u>**Если это общественная ветка
(с ней работает больше 1 человека), тогда `force-push-ы` запрещены на законодательном уровне**</u>: иначе ты рискуешь потереть
коммиты других пользователей ветки (именно по этому запрещают force-push-ы в main/master и прочие общие ветки).

### Когда нужно забрать правки из ветки, в которой ты работаешь не один
Ветки main/master/staging - частные случаи. С ними всё понятно. Когда кто-то добавляет коммиты в твою ветку, тебе нужно
спулить (git pull) их к себе в локальную ветку: `git pull origin branch_name`. При pull-е кода возможны конфликты.
Особенно, если кто-то переписал историю в ветке, откуда ты забираешь код.
